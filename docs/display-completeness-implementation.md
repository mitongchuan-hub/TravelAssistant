# 优化2：卡片日期完整性与有限纠错

实现日期：2026-10-11。

## 行为

展示请求使用保存的计划需求快照日期。动态Schema限定days.minItems=maxItems=行程天数，date限定为对应日期窗口；本地仍检查数量和逐日顺序，拒绝重复、错序和窗口外日期。共享基础Schema不被修改，无日期窗口时保持原协议。

第一次响应仅在JSON、Schema或日期校验失败时允许纠正一次。纠错继续发送同一原文与日期，附前次输出和明确校验错误。原文是唯一事实依据，缺失日使用空items并说明缺失，不复制或新增活动凑天数。

预算继续独立于业务：默认180秒，最多2个实际SDK请求，协议兼容请求也计数。剩余不足60秒、预算用完、旧任务作废或出现前台业务时不追加纠错。网络故障/超时不自动重试，二次校验失败继续保留已交付原文和手动重试入口。
