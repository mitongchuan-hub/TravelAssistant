# 衣物、住宿、天气合并为一次LLM提取：实验结果

日期：2026-10-12。状态：12次固定原文测试及人工评审已完成，单次合并候选值得继续验证；尚未接入生产。

## 结论

把衣物、住宿、天气设为独立栏目，并与每日行程、预算和核实事项合并到一次LLM响应后，本轮衣物12/12保留，有多晚住宿的6份均保留候选酒店及待确认信息，天气12/12提取了原文已有预报。此前两次提取实验衣物仅8/12非空，七日1/3；本轮七日3/3保留。

这些是相同四份原文上的覆盖改善，不证明所有新输入都能提取完整，也不代表整体语义验收已通过。仍发现按时段补算时长、推导入住时刻、概览数量错误、核实时间适用对象改变和建议限定丢失等问题。

## 实现与调用

新增`tests/performance/display_combined_experiment.py`与专用提示词，通用实验执行器支持`--strategies combined`。

一次响应包括：

- preparation.clothing：原文明示衣物与装备，不根据天气补建议。
- preparation.accommodation：区域、候选酒店/地址、晚数/预算、预订与房态/取消/含早待确认。
- weather：原文日期表达、天气、气温、降水概率、查询时间和预报复核提醒。
- 原有title、overview、budget_note、days、pending_items、risks。

请求结构把preparation和weather放在长days列表之前。实验同时修改字段组织、提示词与Schema，不能把覆盖改善单独归因于天气字段或字段顺序。

预算为180秒、最多1次实际SDK请求，无工具、无纠错。字段内容由LLM提取；程序只校验结构/日期，不按评审清单补写事实。Schema版本为`1.1-weather-experiment`，与生产1.0分开；公共行程字段仍通过原校验器，衣物/天气不会为兼容旧协议被程序清空。

生产展示入口、后台调度、持久化与页面没有因实验切换。天气栏目目前仅在实验结果中存在，还未作为生产页面能力交付。

## 原文对照

沿用71项主清单，新增18项天气清单，共267项逐样本人工核对。清单与预期只用于评审，不发送给LLM。

本轮18项天气事实检查在所有适用样本均通过：

- 当天样本保留气温及降水最高约限定；原文没有明确天气查询时间时保持null。页面当天的路线查询日期10月11日没有借作天气查询日期。
- 三日保留14/15/16日天气、温度与≤12/41/49%以及天气查询日期10月11日；出行前一周复核在天气或核实清单中保留。
- 七日只提供10月14日前后阴/约18–26°C与17日毛毛雨/降水约25%两处已知预报；前后、约与未知查询时间保留。没有编造剩余日期的天气数值。

部分输出仍将全程天气复核提醒作为一个无天气数值的列表条目，或将衣物建议重复到天气备注。它们没有新增预报数值，但天气结构及栏目去重仍可改善，不能用非空指标代替分工准确性。

整体专项结论：6份在当前清单及补充观察中未发现重大问题，5份失败，1份存在候选措辞歧义。该结论不是穷尽自然语言质量通过率；源行程事实是否真实也不由展示提取自动证明。
