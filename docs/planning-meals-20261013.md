# 行程用餐约束

2026-10-13，用户确认将用餐完整性、区域衔接和预算一致性纳入规划提示词。本次仅修改规划及共同规则，并新增独立真实模型验收数据；不按饭点关键词由程序硬插用餐，不自动补餐厅事实，不修改历史模型输出。

## 规则

- 按抵离窗口、当地时间、用户习惯和已有安排覆盖相关餐次；正常餐时留用餐机会，不连排景点或交通而漏餐，也不机械为每天补三餐。
- 每餐说明时段、用餐区域或有依据的候选、忌口、预留与预算口径，并与前后活动衔接。未知区域距离与接驳保留未知，不只写“附近吃饭”。
- 未要求具体店名时给区域、餐饮类型和选择标准；要求具体门店时按工具查询，不保证未核实的营业、排队、成分或过敏安全。
- 预约、含餐、自带餐、已吃过和明确不用餐沿用用户安排，不另造一餐或重复支出。深夜抵达正餐按需，早离站可提前准备简餐；酒店/车站供应不默认。离站后餐次不塞入窗口内。
- 明确人数与餐次；逐餐金额按人数、区间上界核对全程额度，两人合计不再乘人数。全程已有额度时按其分配；也可逐餐注明共用额度，不编单价。已付、含餐、自带餐按预算覆盖说明是否新增支出。
- 共同规则限制修改范围：整体生成/重排检查餐次，局部修改只动获授权部分，餐厅查询不扩大成全日行程。

MEAL-002：22:30到、次日07:30走；不新增当晚正餐或夜宵，早晨沿用自带简餐，不假设酒店含早或寻找早餐店。新增饮用水两人20元上限，自备餐不计支出；按确认通勤后安排起床/离店，候车预留与通勤分开。

MEAL-003：保留龙翔桥附近13:00–14:00预约午餐及两人已付180元，计入900元预算一次；晚餐自带有进食休息时段，不另找店。餐次和既有安排正确，但仍出现未知接驳下的建议到达时间、无证据“免费开放”和区域距离较近等表述，完整事实质量未通过。

MEAL-004：三日完整覆盖两次早餐、三次午餐、两次晚餐，每餐有区域或酒店周边等解决方式；首早已吃、末日晚餐离站后自行解决。两人上限2×50+3×120+2×70=600元（餐饮明确含饮品），总分项600+1000+400+300+200=2500元。仍有无依据门票/免费开放、步行距离、馆区位置和接驳时间表问题，不能称完整事实质量通过。

四例均正常完成，任务与需求机器检查4/4通过；人工用餐核心检查（餐次、区域/解决方式、已有安排、金额口径和额度）4/4符合预期，无连接/超时失败。单次专项不能证明完整规划事实质量、长期稳定性或提速；此前漏保存pace、重复更新、交通事实和房间数等问题没有被本次用餐规则宣称解决。所有失败与残余保留在人工评审，不改原文。
