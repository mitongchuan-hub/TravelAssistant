# V2：Agent 生成旅行攻略网页

## 已确认的产品方向

取消固定的行程卡片界面，由最后一个展示 Agent 根据已保存的行程生成 HTML/CSS。用户在聊天里提出需求、查看网页并继续修改，也可以下载独立 HTML 文件。用户已确认采用受设计规范约束的生成方式，并确认规划与网页生成 Agent 分工。

## 当前实现与改动边界

改造前，规划和修改 Agent 交付 Markdown 行程正文；`display` Agent 将正文提取为 YAML，后台校验后供 Jinja 固定卡片模板使用。业务依据是 `TripPlan.text`、日期、需求快照与查询证据；既有 `days` 和旧展示数据属于兼容记录。

V2 保留正文和业务依据，替换展示生成与消费链路。不要为了展示改造同时重构规划协议。旧展示记录继续可加载，V2 不再把旧卡片作为主界面，也不把生成 HTML 反向解析为业务事实。

## Agent 分工

| Agent | 职责与产物 |
| --- | --- |
| 主 Agent | 判断需求整理、查询、规划、内容修改或页面风格调整，并明确采用候选 |
| 需求 Agent | 整理必填游玩设置及想法墙输入 |
| 查询 Agent | 查询地点、天气和路线，保留证据及未知信息 |
| 规划 Agent | 决定地点顺序、时间、交通和费用，交付行程正文 |
| 修改 Agent | 按用户授权范围更新正文，复核受影响路线 |
| 网页生成 Agent（现有 `display`） | 根据正文、日期和展示偏好生成完整 HTML/CSS；不调用业务工具 |

网页 Agent 保留交通细节、备选条件、估算口径和待核实信息。不能把未知写成确定，也不能新增天气、地点、票价、路线或预约结果。默认采用清晰、轻量的攻略排版，系统字体、统一色彩与间距、可折叠说明，并适配手机与打印。

## 流程与持久化

1. 新建或内容修改：原有候选暂存、校验、提交机制保存正文；后台排队生成网页。
2. 页面生成：读取保存的正文、日期和 `display_style`，返回完整 HTML；服务器完成结构和主动内容检查，封装为 `schema_version=2.0` 的展示数据。
3. 发布：绑定计划 ID、正文哈希、需求快照、展示偏好及任务 ID；过期任务不能发布。
4. 纯风格修改：主 Agent 调用 `restyle_itinerary(plan_ref, instruction)`，生成 `presentation` 候选；只有显式采用后才更新偏好、排队生成。正文、证据、计划 ID 和确认状态保持不变。
5. 内容修改后保留展示偏好，并重新生成网页。纯页面修改不调用规划或修改 Agent。

展示偏好作为 `TripPlan.display_style` 存储，与其他异步展示字段一起排除在业务内容指纹之外。展示版本必须区分同一正文的不同风格任务。生成失败时保留完整文字；风格重生失败时保留已有有效网页，同时说明新版本未生成。

## 用户界面

- 工作区保留聊天、想法墙和游玩设置。移除原来的独立“行程”导航入口及固定卡片主体。
- 聊天页提供“旅行攻略”预览区域。桌面与聊天并排；手机通过按钮打开预览，支持关闭并回到当前聊天。
- 预览提供打开完整网页、下载 HTML、重试生成、确认当前行程和查看文字依据。修改入口回到聊天，不让生成网页自行调用业务接口。
- 旧 `?tab=itinerary` 链接继续可用，进入聊天并打开攻略预览，兼容已有消息和任务结果链接。
- 无行程时显示简短说明；生成中有状态；失败后可重试；原文始终可查看。HTML 源码不进入聊天消息正文。

## HTML 合同与隔离

输出必须是单个完整 HTML 文档，可包裹在一个 `html` Markdown 代码围栏中。服务器限制大小、检查完整文档和可读正文，拒绝脚本、事件处理器、表单、嵌套框架、对象、外部资源标签及危险 URL。允许内联 CSS、语义化内容、列表、表格和 `details/summary`。外部导航只使用 HTTPS 链接并在新窗口打开。

预览使用独立受鉴权的 HTML 响应和 sandbox iframe，不向生成内容开放脚本或同源权限。响应设置 CSP，禁止脚本、联网加载、表单与嵌套内容；下载文件插入同样的 CSP meta。正文和 HTML 均不直接以 `safe` 方式插入宿主 DOM。

网页预览及下载每次检查所属用户、计划 ID、正文哈希、有效网页及展示版本。纯风格生成中或失败时，可继续读取与当前正文匹配的已有网页；新网页发布后旧 URL 返回冲突。正文变化后，旧网页立即不可用，不能下载或预览其他旅行及过期结果。

## 错误处理

- 输出结构不合法时，在独立展示预算允许的情况下纠错一次；不调用规划 Agent。
- 模型不可用、超时或纠错失败，行程正文保持可用，允许用户重试。
- 正文或风格更新后，正在执行的旧任务被替代，不能覆盖最新网页。
- 服务重启沿用现有展示任务恢复规则，已有有效网页可继续预览。

## 验收

1. 最后一个 Agent 直接生成 HTML/CSS，运行时不再要求它返回 YAML/JSON 卡片。
2. 聊天页面能预览、打开和下载攻略，手机能关闭预览继续聊天。
3. 纯风格请求通过显式候选提交，仅更新展示；内容修改仍经过规划/修改能力。
4. 行程确认状态不被风格请求或后台发布重置。
5. 危险 HTML、未登录、跨旅行访问和过期版本均被拒绝。
6. 内容及风格更新、生成失败、重试和持久化恢复有自动化覆盖；既有自动化回归通过。
7. 固定卡片模板不再参与 V2 的正常展示，旧业务数据仍可读取。
