# 同城行程模式清理范围

目标：仅保留从已确认住宿出发并返回的同城游玩。

## 源码改动

1. 删除完整旅行专用提示词 `planning.txt`、`planning_examples.txt`、`revision.txt`、`travel_rules.txt` 和旧需求编辑器 `app/templates/requirements.html`。这些文件均由 Git 跟踪，删除可通过版本管理恢复。
2. `agent_roles.py` 统一加载同城提示词；`agent_runtime.py` 和 `task_runtime.py` 统一使用当前同城能力配置。
3. `planning.py` 只检查住宿地址、住宿城市与已确认位置；日期、人数和预算保持可选。移除抵离车站和跨城旅行生成分支。
4. 创建行程默认同城；需求设置只使用住宿表单；欢迎消息、路线依据及界面只保留同城流程。
5. 将评测夹具和回归测试调整为住宿出发场景，验证生成、修改、展示转换及住宿确认门禁。

## 历史记录边界

- 不删除或批量改写数据库、聊天、行程正文或已保存证据。
- 不将历史记录的模式标记静默改为同城，不推断住宿或坐标。
- 历史记录保留可查看；继续生成或调整前须确认住宿。用户保存有效住宿设置后，该记录才明确转入当前同城流程。
- 为读取历史快照所需的旧字段暂保留为存储兼容字段，不再提供旧模式执行能力。

## 验证

使用项目指定解释器运行 `tests/automated`；检查全部提示词引用与模板路由。验证历史记录可读取、没有住宿不能生成，以及确认住宿后的同城流程。
