# 聊天执行过程 Implementation Plan

> **For agentic workers:** 按用户提供的过程列表参考，在当前会话顺序实施并验证。

**Goal:** 聊天中展示真实的模型／工具执行步骤、状态与耗时，支持展开收起和历史回看。

**Architecture:** ConversationTrace 转发真实事件；白名单投影生成面向用户的进度，存入当前助手消息。复用消息轮询与 SQLite 快照，在最终提交时保留过程。前端使用原生 details，执行时展开、结束时折叠，轮询保持阅读与展开状态。

**Tech Stack:** Python、FastAPI、Jinja2、SQLite、原生 JavaScript/CSS、pytest、本地 Chromium。

## Global Constraints

- 使用现有雾蓝主题，过程属于对应助手消息。
- 步骤只来自实际事件；展示业务名称、简短查询对象、状态、耗时，不展示模型原始输出或请求参数。
- 完成、失败、被新消息替代分别表示；旧任务事件不能更新新消息。
- 过程记录失败不能改变业务执行结果；历史缺少过程时正常显示原消息。
- 保留现有行前信息优化及其他用户文件。
