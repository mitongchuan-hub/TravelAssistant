# 规划提示词重新组织

2026-10-13，按用户授权重组生成规划的提示词。此前“先评价、不改变”的阶段已结束，本轮修改提示词和相关工具描述，沿用原有工具权限、需求校验、任务循环、文字保存和后台展示流程。没有按具体城市或样本编写业务特判，没有提交或推送远程。

## 最终结构

1. 共同原则：先处理本轮明确变更；有效需求、日期窗口与最新工具结果优先于旧上下文。说明事实、建议、未知与人为预留的边界。
2. 动作流程：只记录、记录后查询、生成分别定义步骤；页面已有检查与本轮ready结果复用。完整五组标量回传，以及列表、节奏、备注按明确变更同步的规则保留。
3. 规划方法：先安排抵离、固定事项和必去，再按区域组织主线、用餐、休息与备选；天气和入住条件影响实际选择；预算区分费用单位、分项与机动。
4. 查询策略：优先查询影响可行性的事项；按地点、方向、方式、日期与时间核对旧证据；遵守工具能力、调用预算与停止条件。
5. 交付与核对：概览→逐日→预算→相关准备→合并核实清单；原文完整、条件跟随活动，内部核对不冒充程序验证。

## 关键规则

- travel_window的抵离时刻保持原意，离站、提前到站、从景点出发分别表述。没有系统提供星期时只写日期，不由模型推断闭馆或周末人流。
- 未查询通勤不能借“估算/预留”编数值或推出对应到达与最晚出发时刻。查询通勤耗时与人为候车、安检、休息预留分开，每个方向和方式有自己的依据。
- 未知入住、退房、寄存、开放与预约直接约束活动，并有条件或备选。结尾“待核实”不能替代正文中的条件。
- 雷雨等不适合户外时，室内或休息为主线，天气转好后的户外为备选；首日天气不推广到全程。
- 房间数与房型未知时使用整段住宿总额度及晚数；已知才使用每间每晚×房间数×晚数。各分项、区间上下界和机动相加核对，不保证真实费用必然不超。
- 初始requirements_checked描述进入状态，本轮ready的最新工具结果优先；不因旧false重复检查或提交相同需求。本轮明确节奏须写入changes.pace，不能只在回复中采用。
- 仍保护撤销要求、全局与局部范围、user_quote完整原话、需求缺项承接、外部指令隔离、预算耗尽和未知事实。
