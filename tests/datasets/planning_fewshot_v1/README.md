# 规划少样本固定对照

三例使用真实模型、受控合成事实和内存Store，比较加入少样本前后的同一输入，不向8000写旅行、消息或行程。城市、人数、日期和预算不同于提示词中的示例，观察是否迁移方法或照搬样例。

- FS-001：南京当天往返，3人总额1200元、两餐合计450元，10:20抵达、20:10离站。合成公交去程45分钟、返程55分钟，其他交通方式有各自独立合成值；门票和天气未知。
- FS-002：长沙2天1晚，2人总额1500元，14:40抵达、次日15:50离站，抵达前已吃午餐，酒店位置与房间数未定；双向路线均返回失败。
- FS-003：西安4人，只把总预算3600改为4200、节奏改为慢一些，其他需求沿用，明确不生成。

```powershell
& E:\anaconda\envs\TravelAssistant\python.exe -X utf8 -B tests/performance/check_planning_prompt.py --dataset tests/datasets/planning_fewshot_v1/cases.json --output "$env:TEMP\planning-fewshot-new-run"
```

执行器按案例串行，保存完整原文、工具、模型耗时、token、源码指纹和业务库指纹。使用新的空输出目录，连续两次连接/超时失败停止。每例`review`列出人工判断项；机器检查通过仅验证任务、需求、必要工具与授权。

本次先执行全部before，再执行全部after，每条件每例一次。输入、日期和工具资料固定，结果分别保留。它可以观察执行与表达差异，不能量化稳定的质量改善或因果提速；SDK耗时包含网络、排队、预填充和生成。

生成示例与实际用户需求不会参与模型训练或程序硬匹配。少样本只进入planning角色，查询、修改、意图和闲聊的提示词沿用当前实现；不恢复review角色。
